# files/03_yaml_ad_hoc — примеры YAML для практики 3

Каталог относится к практике 3 «Язык YAML и ad-hoc управление»
(`3_yaml_ad_hoc.txt`). Здесь лежат только примеры YAML: они и есть
предмет изучения в первой части практики. Плейбуков, ролей и готовых
скриптов в каталоге нет — ad-hoc команды практики студент набирает
в терминале сам.

## Что за файлы

| Файл | Шаг практики | Что показывает |
|---|---|---|
| `01_scalars.yml` | шаг 3 | Скаляры: строка, число, логическое значение; комментарии; кавычки там, где без них значение сломается; границы документа `---` и `...` |
| `02_lists.yml` | шаг 4 | Списки: блочная и короткая (потоковая) запись, отступ у дефисов, список словарей |
| `03_dicts.yml` | шаг 5 | Словари, вложенность, словарь внутри словаря, список словарей на верхнем уровне |
| `04_multiline.yml` | шаги 6 и 7 | Типы-ловушки (`true` против `"true"`, `yes` как логика, `0644` числом и строкой, `2.19`, `007`) и многострочные значения `\|`, `>`, `\|-` |
| `05_broken.yml` | шаг 8 | Намеренная ошибка отступа. Нужна, чтобы получить настоящий текст `yaml.scanner.ScannerError`, а не описание ошибки словами |

## Как использовать

1. Наберите файлы руками в рабочем каталоге курса на управляющей
   машине — практика печатает их содержимое полностью:

   ```
   mkdir -p ~/ansible-lab/yaml
   cd ~/ansible-lab/yaml
   ```

   Каталог `files/03_yaml_ad_hoc` нужен, чтобы взять готовое, если
   что-то не набралось, и чтобы сравнить свой файл с эталоном.

2. Проверьте любой файл до запуска Ansible:

   ```
   python3 -c "import yaml, sys; yaml.safe_load(open(sys.argv[1]))" 01_scalars.yml
   ```

   Молчание и код возврата 0 означают, что YAML разбирается. PyYAML
   уже установлен в виртуальном окружении `~/ansible-venv` вместе
   с Ansible: команду нужно запускать из активированного окружения
   или поставить `python3-yaml` в системный Python.

3. Посмотрите, во что YAML превращается после разбора, — это лучший
   способ увидеть разницу между `"0644"` и `0644`:

   ```
   python3 -c "import yaml, sys; print(yaml.safe_load(open(sys.argv[1])))" 04_multiline.yml
   ```

## Важно про `05_broken.yml`

Этот файл **не разбирается намеренно**. `python3 -c ... 05_broken.yml`
завершается ошибкой, `ansible-lint` отвечает на него ошибкой правила
`load-failure`, а `tools/validate_files.py` сообщает, что YAML
в этом файле не читается. Так и задумано: ошибка — учебный материал.

Правильный вид этого файла — четыре пробела у строки `port`, то есть
на одном уровне с `name`. Исправлять файл в каталоге не нужно:
исправьте свою копию в `~/ansible-lab/yaml`, а после проверки
верните ошибку обратно, если хотите повторить разбор.
