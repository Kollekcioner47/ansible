# files/13_storage_lvm — файлы практики 13

Здесь лежат файлы практики 13 «Хранилище: диски, LVM, файловые системы»:
плейбуки шагов и переменные по семействам ОС. Это не готовое решение
«запусти и сдай», а те самые файлы, которые студент набирает руками:
их содержимое напечатано и в тексте практики `13_storage_lvm.txt`.
Служебные повторы (`pre_tasks` с `include_vars`, установка пакетов,
задачи вывода `vgs`, `findmnt`, `df`) в тексте практики местами показаны
сокращённо, знаком `...`; полный текст всегда лежит здесь.

Здесь же — два файла переменных `vars/Debian.yml` и `vars/RedHat.yml`.
В `13_storage_lvm.txt` файл `vars/RedHat.yml` напечатан фрагментом:
в нём те же имена переменных, что и в `Debian.yml`, и отличаются только
значения `storage_fstype`, `storage_grow_tool` и `storage_packages`.

Файлы рассчитаны на рабочий каталог курса `/home/engineer/ansible-lab`
на управляющей машине `control`: там уже лежат `inventory.ini`,
`ansible.cfg` и `group_vars/` из практики 2. Каталог `vars/` из этой
практики дополняет `group_vars/`, а не заменяет его.

## ВНИМАНИЕ: ЭТИ ФАЙЛЫ РАЗМЕЧАЮТ ДИСК

Плейбуки `02_parted.yml` и `07_full_storage.yml` создают таблицу
разделов на диске `/dev/sdb`. Запускать их можно **только** на учебном
стенде и **только** для второго диска, на котором нет данных.

* `/dev/sdb` есть только на `web1`, `web2` и `db1`. На `control`
  второго диска нет — плейбук там просто не выполнится.
* Если на узле нет `/dev/sdb`, плейбук останавливается на `assert`
  до разметки.
* Если с диска что-то смонтировано, плейбук тоже останавливается:
  разметка смонтированного диска уничтожает данные.
* Модуль `community.general.parted` с другим значением `label`
  переписывает таблицу разделов целиком. Ошибка в имени устройства
  или лишний запуск «на рабочей машине» стоит всех данных на диске.

**Чем опасно повторное выполнение.** Сами плейбуки идемпотентны: второй
прогон даёт `changed=0`. Опасны не они, а ручные команды вокруг них:

* повторный запуск `parted mklabel` руками уничтожает таблицу разделов
  вместе с разделами и данными;
* повторный запуск `mkfs.ext4` / `mkfs.xfs` руками создаёт файловую
  систему заново — данные пропадают (в курсе за это отвечает
  `community.general.filesystem` **без** `force: true`);
* `lvreduce` руками уменьшает том и обрезает файловую систему: данных
  после этого нет.

## Как этим пользоваться

Скопируйте каталоги и файлы в рабочий каталог курса, сохранив
структуру (`vars/` — это каталог):

```
cd ~/ansible-lab
cp -r /путь/к/репозиторию/files/13_storage_lvm/. .
```

Проверьте, что получилось:

```
tree -L 2 ~/ansible-lab
```

Шаги практики запускаются по порядку и каждый — отдельным плейбуком:

```
ansible-playbook 01_inspect.yml
ansible-playbook 02_parted.yml
ansible-playbook 03_lvm.yml
ansible-playbook 04_filesystem.yml
ansible-playbook 05_mount.yml
ansible-playbook 06_resize.yml
ansible-playbook 07_full_storage.yml
```

Все команды выполняются из каталога `~/ansible-lab`, иначе Ansible
не найдёт `ansible.cfg`, `inventory.ini` и каталог `vars/`.

Если стенд начинается заново (снимок ВМ до практики), достаточно
одного итогового файла:

```
ansible-playbook 07_full_storage.yml
```

Он выполняет всю работу с нуля и на чистом диске, и на уже размеченном.

## На что обратить внимание

* **`07_full_storage.yml` описывает конечное состояние, а `03_lvm.yml` —
  начальное.** В `03_lvm.yml` том создаётся размером `storage_lv_size`
  (6G), в `07_full_storage.yml` — сразу `storage_lv_size_extended` (8G).
  Если запустить `03_lvm.yml` после `06_resize.yml`, том не уменьшится
  только потому, что в обеих задачах стоит `shrink: false`. Без него
  модуль попытается уменьшить том и упадёт с сообщением
  `Sorry, no shrinking of webdata without force=true.` — уменьшение тома
  без `force: true` запрещено намеренно, оно уничтожает данные.
* **`force: true` в `community.general.filesystem` не используется.**
  Этот параметр означает «создай файловую систему заново, даже если она
  уже есть»: `mkfs` выполняется на каждом прогоне, `changed` не станет
  нулём никогда, а данные пропадут. Модуль без `force` на существующей
  файловой системе ничего не делает.
* **`partprobe` выполняется только после изменения таблицы разделов.**
  Задача помечена `when: parted_result.changed`: перечитывать таблицу
  на диске, разделы которого уже используются LVM, не нужно и вредно.
  На повторном прогоне задача пропускается — это часть `changed=0`.
* **Все читающие команды помечены `changed_when: false`.** Иначе
  `ansible.builtin.command` в отчёте всегда показывает `changed=true`,
  и повторный прогон никогда не даст `changed=0`.
* **Размер тома — точное число, а не процент.** `size: 100%FREE`
  и `size: +2G` не идемпотентны: на каждом прогоне размер получается
  новый. Об этом прямо сказано в документации `community.general.lvol`.
* **`vars/` и `group_vars/` пересекаются по смыслу.** Здесь переменные
  практики собраны в отдельные файлы, чтобы набор файлов читался
  целиком. В рабочем проекте те же значения живут в `group_vars`
  по семействам ОС.
