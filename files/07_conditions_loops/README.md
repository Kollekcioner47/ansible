# files/07_conditions_loops — файлы практики 7

Здесь лежат плейбуки и файлы переменных практики 7 «Условия, циклы,
блоки, обработчики». Это не готовое решение практики, а те самые
файлы, которые студент набирает руками: их содержимое напечатано
и в тексте практики.

## Что за файлы и к какому шагу

| Файл | Шаг практики | Что это |
|---|---|---|
| `01_when.yml` | шаг 2 | Условия `when`: факты, переменные, результат `register`, операторы `==`/`!=`/`in`/`is defined`, скобки, `changed_when` |
| `02_two_families.yml` | шаг 3 | Два семейства «в лоб»: `apache2` и `httpd` двумя задачами с `when` на каждое действие |
| `03_blocks.yml` | шаг 4 | `block` с одним `when` на блок, `rescue` с откатом, `always` с итогом; второй play падает намеренно |
| `04_loops.yml` | шаг 7 | Циклы `loop` по списку, словарь через `dict2items`, `loop_control` (`label`, `index_var`, `pause`), вложенный цикл через `product` |
| `05_until.yml` | шаг 8 | Ожидание готовности службы: `until`, `retries`, `delay`, тест `search` |
| `06_handlers_tags.yml` | шаги 9–10 | Итоговый плейбук: переменные семейств, обработчики с `listen`, теги, `changed=0` на втором прогоне |
| `vars/Debian.yml` | шаг 5 | Переменные Ubuntu: пакет, служба, каталог конфигурации, корень сайта, межсетевой экран |
| `vars/RedHat.yml` | шаг 5 | Те же имена для Rocky Linux: `httpd`, `/etc/httpd/conf.d`, `firewalld` |

## Как этим пользоваться

Файлы практики 7 складываются в рабочий каталог курса — рядом
с инвентарём и `ansible.cfg` из практики 2:

```
/home/engineer/ansible-lab/
├── ansible.cfg
├── inventory.ini
├── group_vars/
├── host_vars/
├── vars/
│   ├── Debian.yml
│   └── RedHat.yml
├── 01_when.yml
├── 02_two_families.yml
├── 03_blocks.yml
├── 04_loops.yml
├── 05_until.yml
└── 06_handlers_tags.yml
```

Скопировать готовое можно так (каталог `files/07_conditions_loops` —
из репозитория курса):

```
cd ~/ansible-lab
cp -r <репозиторий>/files/07_conditions_loops/. .
```

Запускать плейбуки нужно **из каталога `~/ansible-lab`**: Ansible ищет
`ansible.cfg` только в четырёх местах — в переменной `ANSIBLE_CONFIG`,
в текущем каталоге, в `~/.ansible.cfg` и в `/etc/ansible/ansible.cfg` —
и вверх по каталогам не поднимается. Из подкаталога не нашлись бы
ни `inventory.ini`, ни `remote_user` из практики 2. Каталог `vars/`
лежит рядом с плейбуками: путь `vars/{{ ansible_os_family }}.yml`
в задаче `include_vars` отсчитывается от каталога плейбука.

```
cd ~/ansible-lab
ansible-playbook --syntax-check 01_when.yml
ansible-playbook 01_when.yml
```

## На что обратить внимание

* **Путь к `vars/`.** Если перенести `05_until.yml` или
  `06_handlers_tags.yml` в другой каталог, `include_vars` их запустит,
  но файл `vars/Debian.yml` не найдётся, и задача упадёт с
  `Could not find or access ...`.
* **Имена переменных совпадают с практикой 2.** В `group_vars/debian.yml`
  и `group_vars/redhat.yml` из практики 2 объявлены те же имена
  `web_package` и `web_service` с теми же значениями. Значения
  совпадают, поэтому конфликта нет; переопределять их в одном месте
  всё равно правильнее — об этом в шаге 5 практики.
* **`03_blocks.yml` падает намеренно.** Второй play ставит пакет
  `lab-extra-package`, которого нет ни в Ubuntu, ни в Rocky Linux.
  Так видно, что делает `rescue`; в итоговом выводе будет
  `rescued=1`, а не `failed=1`. Это учебный опыт, а не ошибка стенда.
* **`pause: 1` в `04_loops.yml`** замедляет создание каталогов
  на три секунды. В учебном стенде пауза нужна только для того,
  чтобы параметр был виден в выводе.
* **Межсетевой экран в файлах не открывается.** Упоминаются `ufw`
  и `firewalld`, но правила для них — практика 9: там для каждого
  семейства свой модуль.
* **Паролей здесь нет.** Параметры подключения заданы пользователем
  и ключом из практик 1–2; учебный пароль `Console47` в файлы
  практики 7 не попадает.
