# files/08_files — файлы практики 8

Здесь лежат файлы практики 8 «Файлы, права и текстовые конфигурации».
Это не готовое решение практики, а те самые файлы, которые студент
набирает руками: их содержимое напечатано и в тексте практики
`8_files.txt`.

Бинарных файлов здесь нет и быть не должно: в репозитории курса
лежат только тексты. Архив сайта собирается на стенде прогоном
плейбука `05_archive.yml`, картинок на учебной странице нет.

## Что за файлы и к какому шагу

| Файл | Шаг практики | Что это |
|---|---|---|
| `site/index.html` | шаги 4–5 | Главная страница учебного сайта: то, что копирует задача `ansible.builtin.copy` |
| `site/style.css` | шаги 4–5 | Таблица стилей сайта: второй файл дерева, на котором видно права 0644 |
| `conf/sshd_hardening.conf` | шаг 7 | Образец фрагмента sshd с комментариями: так выглядит файл `/etc/ssh/sshd_config.d/20-sshd-hardening.conf` после правки |
| `conf/hosts.append` | шаг 9 | Строки блока для `/etc/hosts`; их подставляет `lookup('ansible.builtin.file', ...)` в задаче `blockinfile` |
| `templates/cron.j2` | шаги 4–5 | Шаблон задания cron для `/etc/cron.d/site-check`; команда записана одной строкой, потому что cron не понимает переноса обратным слэшем |
| `01_copy.yml` | шаг 5 | Каталог сайта, копирование содержимого, задание cron |
| `02_permissions.yml` | шаги 6 и 12 | Права на файлы, бит `setgid` на каталоге, проверка через `stat` и `assert` |
| `03_lineinfile.yml` | шаг 7 | Две настройки sshd в отдельном файле каталога `sshd_config.d`, проверка `validate: sshd -t -f %s` и разбор действующих значений из `sshd -T` |
| `04_blockinfile.yml` | шаг 9 | Управляемый блок в `/etc/hosts` с маркерами `BEGIN` и `END` |
| `05_archive.yml` | шаг 13 | `archive`, `fetch` и `unarchive` с `remote_src: true` |

## Как этим пользоваться

Файлы практики 8 складываются в рабочий каталог курса на управляющей
машине `control` рядом с `inventory.ini` и `ansible.cfg` из практики 2.
Каталоги `site/`, `conf/` и `templates/` должны оказаться рядом
с плейбуками: `copy` и `template` ищут файлы относительно плейбука.

```
/home/engineer/ansible-lab/
├── ansible.cfg
├── inventory.ini
├── group_vars/
├── host_vars/
├── site/
│   ├── index.html
│   └── style.css
├── conf/
│   ├── sshd_hardening.conf
│   └── hosts.append
├── templates/
│   └── cron.j2
├── 01_copy.yml
├── 02_permissions.yml
├── 03_lineinfile.yml
├── 04_blockinfile.yml
└── 05_archive.yml
```

Копировать надо содержимое каталога, а не сам каталог: точка в конце
`files/08_files/.` кладёт файлы прямо в `~/ansible-lab`, иначе они
окажутся в `~/ansible-lab/08_files`, а плейбуки ищут `site/`,
`conf/` и `templates/` рядом с собой. Каталог `files/08_files` —
из репозитория курса:

```
scp -r files/08_files/. engineer@10.0.2.5:/home/engineer/ansible-lab/
```

Если репозиторий лежит на управляющей машине, то же самое делается
на месте, из каталога `~/ansible-lab`:

```
cp -r /путь/к/репозиторию/files/08_files/. .
```

Запуск — из каталога `~/ansible-lab`, иначе Ansible не найдёт
`ansible.cfg`, инвентарь и файлы `site/`, `conf/`, `templates/`:

```
cd ~/ansible-lab
ansible-playbook --syntax-check 01_copy.yml
ansible-playbook 01_copy.yml
ansible-playbook 02_permissions.yml
ansible-playbook 03_lineinfile.yml
ansible-playbook 04_blockinfile.yml
ansible-playbook 05_archive.yml
```

Порядок важен: сначала каталог и файлы (`01_copy.yml`), потом права
(`02_permissions.yml`) и только потом конфигурации и архив. Второй
прогон каждого плейбука, кроме `05_archive.yml`, должен дать
`changed=0`.

## На что обратить внимание

* **Права — строкой в кавычках.** В плейбуках везде записано
  `mode: "0644"`, `mode: "0755"` и `mode: "2755"`. Запись `mode: 0644`
  без кавычек YAML разбирает как число; Ansible её принимает, но
  выдаёт предупреждение, а `ansible-lint` ругается правилом
  `risky-octal`.
* **`setgid` только на каталоге сайта.** Права 2755 стоят на
  `/var/www/html/site`, а не на всём `/var/www`: у соседних каталогов
  могут быть свои договорённости.
* **`sshd` правится отдельным файлом.** `conf/sshd_hardening.conf` —
  образец содержимого файла `20-sshd-hardening.conf` с пояснениями;
  сам плейбук пишет в этот файл две строки модулем `lineinfile`.
  Основной `/etc/ssh/sshd_config` не трогаем: он принадлежит пакету.
* **Имя `20-...` выбрано не случайно.** `sshd` берёт ПЕРВОЕ найденное
  значение параметра, а файлы каталога `sshd_config.d/` подставляет
  по алфавиту: `Include` разворачивает `sshd_config.d/*.conf`
  в лексикографическом порядке. На Ubuntu уже лежит
  `50-cloud-init.conf`, а имя `20-...` идёт раньше него, поэтому
  наши значения побеждают. Имя `55-...` читалось бы после cloud-init
  и проиграло бы ему. Рядом лежит `10-lab-nopassword.conf`
  из практики 2: разные префиксы показывают, чей файл что делает,
  а одинаковые тоже допустимы — `sshd` разберёт их по полному имени.
* **Действующее значение проверяют, а не читают файл.**
  `03_lineinfile.yml` после правки выполняет `sshd -T` и разбирает
  его вывод в `assert`: важно то, что `sshd` применил, а не то, что
  написано в нашем файле.
* **`validate` обязателен.** Без него опечатка в конфигурации sshd
  применяется, и доступ к машине по SSH теряется. Одна строка
  `validate: "sshd -t -f %s"` дешевле выезда в дата-центр.
* **`conf/hosts.append` — не готовый `/etc/hosts`.** Это только
  строки блока. Задача `blockinfile` вставит их между маркерами
  `BEGIN` и `END`, а остальное содержимое файла не тронет.
* **`remote_src: true` — только для архива на узле.** В
  `05_archive.yml` архив сначала собирается модулем `archive`
  на самом узле, поэтому распаковывается с `remote_src: true`.
  Архив, собранный на управляющей машине, распаковывают без этого
  параметра.
* **Адреса и пароли.** `10.0.2.5`, `10.0.2.11`, `10.0.2.12`
  и `10.0.2.13` — учебные адреса стенда курса. На своём стенде
  замените их в инвентаре практики 2, а не в этих файлах.
