# files/11_regex_configs — файлы практики 11

Здесь лежат файлы практики 11 «Регулярные выражения и точечная правка».
Это не готовое решение практики, а те самые файлы, которые студент
набирает руками: их содержимое напечатано и в тексте практики
`11_regex_configs.txt`.

Образцы конфигураций (`conf/*.in`) — учебные. Они нарочно выглядят как
настоящие файлы пакета: часть параметров закомментирована, часть задана
значениями по умолчанию. На таких файлах и видно, зачем нужны `regexp`,
якоря и обратные ссылки: правку делают по выражению, а не по точному
тексту строки.

## Что за файлы и к какому шагу

| Файл | Шаг практики | Что это |
|---|---|---|
| `conf/sshd_config.in` | шаги 5, 7, 9, 13 | Образец drop-in файла `/etc/ssh/sshd_config.d/20-sshd-hardening.conf`: параметры sshd закомментированы, их включают задачи `lineinfile` |
| `conf/chrony.conf.in` | шаги 5, 11 | Образец `/etc/chrony.conf` для Rocky Linux 10: два сервера внешнего пула NTP, которые заменяет `replace` |
| `conf/resolv.conf.in` | шаги 5, 11 | Образец `/etc/resolv.conf`: три сервера имён, из них один внешний — его убирает `replace` |
| `01_regexp.yml` | шаги 7 и 8 | `lineinfile`: `regexp` против `search_string`, `insertafter` с `firstmatch`, `state: absent`, `backup`, `validate`, три параметра sshd одной задачей через `loop` по списку словарей `{regexp, line}`, обработчик перезапуска sshd |
| `02_backrefs.yml` | шаг 9 | `backrefs: true`: группы выражения в `line` (`\1`, `\2`) и промах выражения, при котором файл не меняется вообще |
| `03_blockinfile_markers.yml` | шаг 10 | Два управляемых блока в `/etc/hosts`: свой `marker`, `marker_begin` и `marker_end`, удаление блока через `state: absent` |
| `04_replace.yml` | шаг 11 | `replace` на `chrony.conf` (`backup`, `validate: chronyd -p -f %s`) и на учебной копии `resolv.conf` (экранирование точки, замена домена поиска, `assert` по результату) |
| `05_find_age.yml` | шаг 12 | `find` с `patterns`, `age`, `size`, `recurse` и `register`, удаление найденных `*.bak` и `*~`, просмотр больших журналов без удаления; у `age` и `size` плюс подразумевается, минус меняет направление |
| `06_validate.yml` | шаг 13 | `validate` в действии: задача с опечаткой падает, `assert` подтверждает, что `validate` отклонил файл, затем записывается верная строка |

## Как этим пользоваться

Файлы складываются в рабочий каталог курса на управляющей машине
`control` рядом с `inventory.ini` и `ansible.cfg` из практики 2.
Каталог `conf/` должен оказаться рядом с плейбуками: `copy` ищет
`src` относительно плейбука.

```
/home/engineer/ansible-lab/
├── ansible.cfg
├── inventory.ini
├── conf/
│   ├── sshd_config.in
│   ├── chrony.conf.in
│   └── resolv.conf.in
├── 01_regexp.yml
├── 02_backrefs.yml
├── 03_blockinfile_markers.yml
├── 04_replace.yml
├── 05_find_age.yml
└── 06_validate.yml
```

Скопировать готовое можно так (каталог `files/11_regex_configs` — из
репозитория курса). Копируется содержимое каталога, а не сам
каталог: иначе файлы лягут в `~/ansible-lab/11_regex_configs`,
а плейбуки ищут `conf/` рядом с собой.

```
scp -r files/11_regex_configs/. engineer@10.0.2.5:/home/engineer/ansible-lab/
```

Если репозиторий уже лежит на управляющей машине, то же самое
делается на месте, из каталога `~/ansible-lab`:

```
cd ~/ansible-lab
cp -r /путь/к/репозиторию/files/11_regex_configs/. .
```

Запуск — из каталога `~/ansible-lab`, иначе Ansible не найдёт
`ansible.cfg`, инвентарь и каталог `conf/`:

```
cd ~/ansible-lab
ansible-playbook --syntax-check 01_regexp.yml
ansible-playbook 01_regexp.yml
ansible-playbook 02_backrefs.yml
ansible-playbook 03_blockinfile_markers.yml
ansible-playbook 04_replace.yml
ansible-playbook 05_find_age.yml
ansible-playbook 06_validate.yml
```

Порядок важен: `01_regexp.yml` кладёт файл `20-sshd-hardening.conf`
из образца, `02_backrefs.yml` и `06_validate.yml` правят уже
существующий файл, а `04_replace.yml` кладёт свои образцы на место сам.
Имя то же, что у drop-in файла практики 8, а задача `copy`
с `force: false` чужую работу не затирает: образец встаёт на место
только там, где файла ещё нет.
Каждый плейбук, кроме описанных ниже случаев, на втором прогоне даёт
`changed=0`.

## Где какой узел

* `01_regexp.yml`, `02_backrefs.yml`, `03_blockinfile_markers.yml`,
  `05_find_age.yml`, `06_validate.yml` работают на группе `web`
  (`web1`, `web2` — Ubuntu 26.04 LTS);
* первый play `04_replace.yml` работает на группе `db` (`db1` —
  Rocky Linux 10): там стоит `chrony`, и команда `chronyd -p -f %s`
  проверяет конфигурацию до подмены файла;
* второй play `04_replace.yml` работает на группе `web` и правит
  **учебную копию** `/etc/resolv.conf.lab`, а не живой
  `/etc/resolv.conf`: на Ubuntu им управляет `systemd-resolved`,
  на Rocky — NetworkManager, и правка живого файла исчезнет при первой
  же перезагрузке. Что живой файл не тронут, видно по самому play:
  все его задачи работают с переменной `resolv_copy`
  (`/etc/resolv.conf.lab`), и `assert` в конце читает ту же копию.
  Сам живой файл смотрят на узле командой `ls -l /etc/resolv.conf`:
  там символическая ссылка на `stub-resolv.conf`.

## На что обратить внимание

* **`backup: true` не заменяет систему контроля версий.** Копии
  `*.bak` с отметкой времени нужны на первый прогон по живой машине;
  сам файл конфигурации всё равно хранят в репозитории. В учебной
  задаче они же становятся материалом для `find` в `05_find_age.yml`.
* **`force: false` у `copy` — это и есть идемпотентность образца.**
  Образец `conf/sshd_config.in` кладётся на место только тогда, когда
  файла ещё нет. Если класть его каждый раз, первый же прогон вернёт
  закомментированные строки, `lineinfile` снова их заменит, и плейбук
  никогда не даст `changed=0`.
* **Одинарные кавычки в `regexp`.** В одинарных кавычках YAML обратный
  слеш попадает в выражение как есть: `'^\s*PermitRootLogin\s'`.
  В двойных кавычках `"\s"` — ошибка разбора YAML, там пришлось бы
  писать `"\\s"`. Подробнее — шаг 4 практики 11.
* **`validate: "sshd -t -f %s"` обязателен.** Без него опечатка
  в конфигурации sshd применяется, и доступ к машине по SSH теряется.
  `06_validate.yml` показывает это нарочно: задача с опечаткой падает,
  файл на узле остаётся прежним.
* **`validate` не умеет конвейеров.** Команда проверки запускается без
  оболочки, поэтому `%s` — единственный способ передать ей временный
  файл, а `|`, `$( )` и подстановки в ней не работают.
* **Маркер без `{mark}` размножает блок.** Подстановка `{mark}`
  превращается в `BEGIN` или `END`; без неё `blockinfile` не находит
  свой блок и вставляет его заново на каждом прогоне.
* **У `age` и `size` плюс подразумевается.** `age: 7d` и `size: 10M`
  означают «не меньше указанного»: файл старше недели и файл больше
  10 МБ. Плюс не пишут — он подразумевается по умолчанию, а модуль
  разбирает только число с необязательным минусом. Минус меняет
  направление на «не больше указанного»: `age: -1w` — файлы,
  изменённые за последнюю неделю. Значения с плюсом (`+7d`, `+10M`)
  модуль `find` не разбирает и падает с `failed to process age` или
  `failed to process size`.
* **Адреса и имена — учебные.** `10.0.2.5`, `10.0.2.11`, `10.0.2.12`
  и `10.0.2.13` — адреса стенда курса; `0.centos.pool.ntp.org`,
  `control.example.ru` и `lab.local` — имена-заглушки. На своём стенде
  замените их в инвентаре практики 2 и в образцах `conf/`.
